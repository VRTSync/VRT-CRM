#1 - Slice 1: Foundation, Auth, Stylesheet
What & Why
First slice of the VRTSync CRM, an internal tool replacing Zoho for a 4-6 person property maintenance software team. The authoritative build prompt for this slice is attached_assets/SLICE-1-PROMPT_1786988160692.md. Follow its BUILD, CONSTRAINTS, FILES, DONE WHEN, and DO NOT sections exactly. The binding spec is attached_assets/02-SPEC_1786988149595.md (including amendment A1); attached_assets/vrtsync-crm-mockup_1786984786725.html is the approved design; do not redesign anything. Ignore all earlier attached copies of the spec and the build prompt.

This repository starts empty. Build the tree in the prompt's FILES section exactly as written: one /client (Vite React SPA) and one /server (Express JSON API), plain JavaScript, .js and .jsx files only. No TypeScript. No OpenAPI or JSON Schema document, no shared contract package, no monorepo lib or artifacts organization.

This slice delivers: Vite React SPA client, Express JSON API, Postgres with Drizzle, Google OAuth restricted to one Workspace domain (vrtsync.com, read from an environment variable), the users and customers tables only, the application shell (230px navy sidebar, sticky topbar, 1400px content canvas at 22px padding), the stylesheet lifted as-is from the mockup with the six cleanups in BUILD item 5 applied, and a rerunnable seed script. Each sidebar item routes to an empty content canvas with the correct screen title. No screen content, no other tables, no other features.

Done looks like
(DONE WHEN, from the build prompt)

A company Google account signs in, a non-company account is rejected with a clear message and no user record created.
First sign-in creates a user with null role. Role assignable only by a user whose own role is owner, via one endpoint.
customers table matches spec 9 as amended by A1: acreage and fully_maintained are present, and no other property profile columns exist on customers. Stage is an enum with exactly nine values: lead, discovery, proposal, signed, mapping, data_load, training, live, churned.
The stylesheet is lifted from the mockup with all six BUILD item 5 cleanups fixed.
The eight --stage-* tokens exist and no stage color is an inline hex.
The shell renders and matches the mockup at 1440x900 and at 390px wide.
No Tailwind in package.json.
Rerunnable seed script: four users covering sales, mapping, admin, owner, plus one null-role user, and six to eight communities spread across stages drawn from the mockup's names and figures.
Out of scope
Everything in the prompt's DO NOT section, including: contacts, notes, tasks, task_templates, template_items, projects, and customer_layers tables; irrigation_zones, snow_lots, walk_miles, bed_count, common_areas, tree_inventory columns (removed by amendment A1); any real screen content (empty canvases only); settings, notifications, profile editor, admin panel, onboarding, dark mode, landing page; any auth path other than Google OAuth; server-rendered pages; TypeScript; OpenAPI or shared contract packages; extra fields on users or customers; Tailwind, shadcn, or any CSS framework or utility library.

Steps
Remove scaffolding -- Delete the pnpm monorepo scaffolding: lib/db, lib/api-spec, lib/api-client-react, lib/api-zod, and the artifacts directory, plus their workspace wiring. Place the mockup HTML at the repository root as /vrtsync-crm-mockup.html (do not modify or serve it).
Scaffold /client and /server -- Exactly per the prompt's FILES tree, plain JavaScript, with drizzle.config.js and .env.example (names only) at the root.
Stylesheet port -- Extract the mockup's style block into client/src/styles/tokens.css (token block only), base.css, and components.css, keeping every component class name, changing no values except the six cleanups in BUILD item 5 (stage tokens, raw hex promotion or one-off comments, unused token decision, em dash removal, scaffolding removal, deterministic avatar color from user id).
Database -- Provision Postgres; Drizzle schema in server/db/schema.js with users and customers exactly as listed in BUILD item 6 (customers carries acreage and fully_maintained and no other property fields, per A1); migration setup; rerunnable seed script in server/db/seed.js that resets and repopulates.
Auth -- Google OAuth in server/auth.js, domain restriction to vrtsync.com read from an environment variable, first-sign-in user creation with null role, owner-only role assignment endpoint. No passwords, invitations, or reset flow.
Shell -- Sidebar (Work: Dashboard, Customers, Team To-Do, Projects; Setup: Task Templates, Spec), sticky topbar (title, subtitle, search, trailing primary action), 1400px content canvas at 22px padding, each nav item routing to an empty canvas with the correct title; sidebar collapses to a horizontal strip below the tablet breakpoint.
Standing constraints for every slice: plain CSS with custom properties only; row vertical padding 8px, table cells 10px, card headers 12px; never --accent as a text color, use --accent-ink; no em dashes or en dashes anywhere including code, comments, and UI copy; no raw hex outside the token block; JSON API only; add nothing not named in BUILD.
