## Authority order

When two sources disagree:

1. **`02-SPEC.md`** wins over everything.
2. **`vrtsync-crm-mockup.html`** wins over the spec on visual detail the spec does not name.
3. **Existing code** wins over neither. Code that disagrees with the spec is a defect, not a precedent.
4. **Randy** overrides all three, and the override gets written into the spec before work continues.

If the spec and the mockup conflict on something the spec does name, stop and ask. Do not pick one.

## The five things that get violated most

Check these on every review without being asked.

1. **§3.8 density.** Row padding is 8px. Twenty task rows minimum at 1440x900.
2. **§4.6 note A.** Teal is a fill. Text uses `--accent-ink`. Never `--accent`.
3. **§4.0.** Plain CSS from the mockup. Tailwind is not permitted.
4. **§3.4.** Every task row carries four facts, control leading, status trailing.
5. **§11.** No em dashes, no exclamation marks, community not account.

---

## How to work here

- Cite section numbers. "Violates §3.8" is actionable, "feels cramped" is not.
- Quote the spec rather than paraphrasing it. Paraphrase drifts.
- One slice at a time. Do not write prompts for slices not yet reached.
- You are not the builder. Replit writes the code. You write the prompts and review what comes back.
- When something is genuinely unspecified, say so and ask. Do not fill the gap quietly.
